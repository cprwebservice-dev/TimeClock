Time-Clock Enterprise V6.11.51
Scope Batch Load + Team Week Selector

1) ปฏิทินจัดกะ > มุมมองรายบุคคล
สาเหตุที่ V6.11.50 ยังได้ 1,000 วัน-พนักงาน:
- การใช้ HTTP Range กับ Set-returning RPC ยังไม่แก้ server max rows ในเคสนี้
- จากภาพ 33 คน x 31 วัน ควรได้ 1,023 วัน-พนักงาน แต่ระบบยังได้ 1,000

V6.11.51 แก้ใหม่:
- ดึงรายชื่อพนักงานจาก ta_get_schedule_filter_options_v61026 ก่อน
- รายชื่อนี้เป็นพนักงานทั้งหมดตาม User Scope ของช่วงวันที่
- แบ่งรหัสพนักงานชุดละ 20 คน
- โหลดตารางกะแต่ละชุดแยกกัน
- 20 คน x 31 วัน = สูงสุด 620 แถวต่อ Request จึงไม่ชน 1,000-row cap
- รวมผลทุกชุดด้วย emp_code + work_date
- แสดงสถานะจำนวนโหลดจริง / จำนวนพนักงานที่คาดตาม Scope
- Search เป็น Client-side อย่างเดียว ไม่ยิงโหลดซ้ำตอนพิมพ์
- ถ้าค้นรหัส Exact แล้วไม่มีจริง จะแจ้งว่าไม่อยู่ใน User Scope/ตัวกรอง

2) ปุ่ม "กำลังโหลด..." ค้าง
- เพิ่ม Single-flight guard ไม่ให้ loadSchedule ซ้อนกัน

- ไม่เก็บข้อความ "กำลังโหลด..." เป็นข้อความเดิมของปุ่มอีก
