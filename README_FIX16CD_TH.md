# TimeClock V6.15.29 FIX16CD — Acting history display

ฐานไฟล์: ZIP FIX16CB ที่ผู้ใช้ส่งมา; ใช้ร่วมกับฐานข้อมูลที่ติดตั้ง SQL FIX16CC แล้ว

## ติดตั้ง

1. แตก ZIP นี้ แล้วนำไฟล์เว็บไปแทนที่ตำแหน่งเดิมใน GitHub repository ที่เผยแพร่ TimeClock โดยให้ index.html อยู่ระดับเดิม ไม่ซ้อนโฟลเดอร์เพิ่ม
2. รอการเผยแพร่ GitHub Pages ของคุณสำเร็จ
3. เปิดเว็บ กด Ctrl+Shift+R แล้วเข้า Acting Manager ด้วย HR Admin
4. ควรเห็นข้อความ “แสดงทุกช่วงวันที่” และรายการย้อนหลัง/ปัจจุบัน/อนาคต พร้อมสถานะเดิม

ไม่ต้องรัน SQL เพิ่มสำหรับชุดนี้ และไม่ต้องกำหนด Acting ซ้ำเพื่อให้รายการปรากฏ
SQL FIX16CC ที่ติดตั้งก่อนหน้ายังคงใช้ต่อได้

## สาเหตุที่พบในโค้ดเดิม

loadActing ใช้ listRange ของหน้ารายการยืมตัว โดยเริ่มต้นที่ต้นเดือนปัจจุบันถึงวันนี้ +90 วัน
ดังนั้น Acting ซึ่งสิ้นสุดก่อนต้นเดือนอาจถูกตัดออก ทั้งที่ยังบันทึกอยู่
รูปที่ส่งมายืนยันเพียงว่ารายการตามเงื่อนไขที่ร้องขอว่าง ไม่ใช่หลักฐานว่าข้อมูลถูกลบ
ยังไม่ได้อ่านแถว Acting จริงจากฐานข้อมูล จึงยังยืนยันไม่ได้ว่ารายการของผู้ใช้สิ้นสุดเมื่อใด

## สิ่งที่แก้

- เรียก RPC เดิมด้วย p_from=null, p_to=null, p_org_id=null เพื่อให้ HR ดูทุกช่วงวันที่
- แสดงคำอธิบายช่วงข้อมูลที่หน้า Acting
- แยกสถานะกำลังโหลด/ไม่พบรายการ/โหลดผิดพลาด
- โหลด Acting แยกจากผลสำเร็จของ Borrow Workspace
- รวมคำขอ Acting ที่ซ้อนกัน และไม่รับผลจาก session เก่าหลังเปลี่ยนบัญชี
- เปลี่ยน cache version ของ app.js ใน index.html และ 404.html

แก้ไฟล์เว็บ 3 ไฟล์: app.js, index.html, 404.html ส่วนไฟล์เว็บอื่นตรงกับต้นฉบับ
ไม่มีการแก้ข้อมูล วันมีผล สถานะ สิทธิ์ Manager/Acting หรือกฎฐานข้อมูล
การเห็นรายการสิ้นสุดแล้วไม่ได้ทำให้สิทธิ์ Acting กลับมาใช้งาน
RPC ตาม SQL ต้นทางที่ตรวจรองรับค่า null เพื่อไม่จำกัดช่วงวันที่ และตรวจ HR_ADMIN ที่ฝั่งเซิร์ฟเวอร์
นิยาม RPC นี้ในฐานจริงไม่ได้อยู่ใน CSV ที่ส่งมาตรวจครั้งก่อน หากถูกเปลี่ยนไปจากต้นทาง อาจต้องตรวจเพิ่ม

## ผลตรวจ

- node --check ผ่าน
- ทดสอบ 8 สถานการณ์ด้วยฟังก์ชันหน้าเว็บจริงและ RPC/DOM จำลอง:
  รายการย้อนหลัง, ผลว่าง, Error และการ escape ข้อความ, response ผิดรูปแบบ,
  คำขอซ้อนกัน, เปลี่ยน session, ผู้ใช้ไม่ใช่ HR, และ Borrow RPC ล้มเหลว
- ยังไม่ได้ทดสอบกับ session และข้อมูล Acting ของผู้ใช้บน Supabase จริง

## หากยังไม่แสดง

ส่งข้อความ Error ที่หน้า Acting ถ้ามี
ถ้าแสดง “ไม่พบรายการ Acting ที่บันทึกไว้” ให้รัน support/ACTING_READ_ONLY_CHECK.sql ใน SQL Editor แล้ว Export ผลทั้งหมดส่งกลับ
ไฟล์นี้อ่านจำนวนรายการ ช่วงสถานะ จำนวนรายการที่ไม่มีหน่วยงานอ้างอิง และนิยาม RPC เท่านั้น ไม่แก้ข้อมูล

## ย้อนกลับหน้าเว็บ

นำ ZIP FIX16CB ต้นฉบับที่ส่งมาก่อนหน้านี้กลับไปเผยแพร่แทนได้ โดย SQL FIX16CC ฝั่งฐานข้อมูลยังใช้ร่วมกันได้
